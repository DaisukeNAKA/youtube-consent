## 1. 実測でわかったこと（#29 のワイヤレス収録）

| 項目 | 実測値 | 判定 |
|---|---|---|
| 真のピーク（32bit float デコード） | ch0 +0.53 / ch1 +0.20 dBFS | **クリップではない** |
| 0 dBFS 超えのサンプル | 1億1,481万中 16〜18 個 | 事実上ゼロ |
| 圧縮の折れ点 | ch1 は約 −18 dBFS から傾き 0.60〜0.76（≒1.5:1）、ch0 は 0.92 | **Clipping Control 作動** |
| 最大1秒窓のピーク | −2.1〜−3.6 dBFS に密集 | 天井あり |

| 長時間平均話声スペクトル比 | 630〜2000 Hz **+7〜+10 dB**、8〜10 kHz **−13〜−15 dB**、125〜200 Hz **−9〜−13 dB** | 胸元ラベリアの指紋 |
| 帯域ごとの S/N | 1〜4 kHz は 36〜45 dB、**8〜10 kHz は 19 dB** | 高域は EQ だけでは戻せない |
| ノイズフロア | −52.3 dBFS RMS | S/N 約33 dB |

### 「詰まった感じ」の正体は2つ

1. **胸元共鳴** — **630〜2000 Hz が +7〜+10 dB 過剰**。胸に付けた無指向性ラベリアの教科書どおりの症状で、これが「こもり」「詰まった感じ」の本体。同時に **8〜10 kHz が 13〜15 dB 不足**して子音が抜けない。
2. **DJI Clipping Control** — 大きな声のときだけ作動する動的な圧縮。e935 + P4next にはこれに相当するものが無い。
3. （副次的）**コムフィルタ** — 分離 4.0 dB・遅延 2 ms でモノラル加算すると理論上リップルは 12.9 dB p-p。ただし話者が動くため長時間平均では均され、実測の細かいリップルは過去回（#28）と有意差が無かった（標準偏差 1.60 dB 対 1.91 dB）。**当初考えていたほど支配的ではない。**

> **前版の訂正（実測のやり直しによる）**
> 前版で「250〜630 Hz が +9〜+12 dB 過剰」と書いたのは**1オクターブずれていました**。正しくは **630〜2000 Hz** です。
> 16384点 FFT・1/3 オクターブ・発話区間のみ・Byrne(1994) の長時間平均話声スペクトルを基準に測り直した結果です。
> 補正 EQ の中心周波数もこれに合わせて全面的に変更しています（5 節）。

## 3. いますぐやること（追加費用ゼロ）

### P4next の設定
1. **MENU → System → Recorder Mode → Multi Track**
   2人が `MIC1.WAV` / `MIC2.WAV` として**別ファイル**で残る。これが最大の効果。
   公式マニュアル p.50 に「**COMP と AI NOISE REDUCTION は個別ファイルにはかからない**」と明記。素の音が残る。
   ※ Lo Cut / TONE / Limiter は信号経路上、録音タップより前段のため**個別ファイルにも焼き込まれる**と推定（マニュアルに明示が無いので、ON/OFF のテスト録音1分で確定できる）。
2. **MENU → USB Audio Interface → Mode → Stereo Mix**
   Multi Track にすると 12ch が送出され、カメラ側で扱えない。
3. **入力レベルは −12〜−6 dBFS**（Zoom 公式ガイドライン）。24bit なので「クリップしないから適当でいい」は成立しない。
4. 48V ファントムは**切る**（e935 はダイナミック。4系統一括スイッチなので注意）。
5. 録音しながら USB でカメラへ送るのは**公式に可能**（マニュアル p.6）。

### 収録の設計
6. **口元 10〜12 cm**。5〜7 cm は40分の無監視収録には近すぎる。
7. **2人が並ぶ配置のままでよい。ただしマイクを外向きに振る**。カーディオイドの背面ヌルを相手の口へ向けるのが分離の本体。
8. 机の反射が **275〜450 Hz にディップ**を作る。天板にフェルトやラグを敷く。
9. Pocket 3 の**「内蔵マイク音声バックアップ」を ON**。同期の保険になる。

### 給電（見落としやすい）
10. Pocket 3 から P4next への給電は不足する可能性が高い。**DC5V 端子に外部給電、または単3電池2本**。
11. 素の Pocket 3 は USB-C が底面の1つだけで、外部マイク使用中は充電できない。バッテリーハンドル（クリエイターコンボ）があれば両立する。

### Premiere での置き換え
12. カメラ音声は**ミュートで残し**、P4next の SD 音声に差し替える。波形同期はタイムライン上の**「同期（Synchronize）」**を使う（「クリップを結合（Merge Clips）」ではない）。
   なぜ必須かというと、USB 経路には2つの上限があるためです。**(a) Pocket 3 の記録は 48 kHz / 16-bit AAC** なので、P4next が 24-bit で出しても記録時点で落ちる。**(b) P4next にはパン（定位）機能が無く**、Stereo Mix モードでは INPUT 1〜4 が USB の L/R に**同一ミックス**として送られる。つまりカメラ音声だけでは、e935 を2本使っても2人を後から個別に扱えません。SD のマルチトラックを使うことが、24-bit よりもまず**2人の分離**を取り戻すために要ります。
13. ズレるのは「カメラ映像 対 P4next の SD 録音」の間だけ。USB 接続中のカメラ音声は映像とズレない。
14. 「速度・デュレーション」は小数2桁までしか入れられず ppm 級のドリフト補正には使えない。必要ならレート調整ツールか Audition。

## 5. ポスプロで「できること・できないこと」

### 5-1 できる（#29 完パケの再レンダリングで実証済み）

長時間平均話声スペクトルからの乖離（RMS）が **12.34 dB → 3.93 dB**。8 kHz の不足が **−26.8 → −8.9 dB**、630〜2000 Hz の過剰が **+7〜+10 → ±2 dB 以内**。

**ワイヤレス素材向けの補正 EQ（5バンド。Premiere / Audition のパラメトリックイコライザーにそのまま入る）**

| | 種類 | 周波数 | Q | ゲイン | 狙い |
|---|---|---|---|---|---|
| 0 | ハイパス | 75 Hz | — | — | 机の振動・衣擦れ |
| 0' | ノッチ | 100 Hz | 幅6 | — | 電源ハム |
| 1 | ローシェルフ | 263 Hz | 1.64 | **+4.35 dB** | 痩せた低域を戻す |
| 2 | ピーク | 829 Hz | 1.53 | **−6.32 dB** | 胸元共鳴の下側 |
| 3 | ピーク | 1652 Hz | 1.11 | **−7.06 dB** | 胸元共鳴の上側（最重要） |
| 4 | ピーク | 3410 Hz | 2.20 | **−4.09 dB** | 硬さ |
| 5 | ハイシェルフ | 5305 Hz | 0.99 | **+5.00 dB** | 子音の抜け |

この5バンドは、#29 の 1/3 オクターブ実測と Byrne (1994) の長時間平均話声スペクトルの差を最小二乗で当てはめて導いたものです（当てはめ誤差 RMS 0.75 dB）。

**順序が重要**: ノイズリダクション → EQ → ディエッサー → コンプ → ラウドネス正規化。
**ノイズリダクションは EQ より前**です。理由は 8〜10 kHz の S/N が 19 dB しかなく、先に EQ で +5 dB 持ち上げるとヒスも一緒に上がるためです。実測でも、ノイズリダクションを先に掛けたほうが到達できる補正量が大きくなりました。

**ハイシェルフの量は好みで変えてよい**数少ない箇所です。

| ハイシェルフ | 乖離 RMS | 8 kHz | サ行ピーク | 印象 |
|---|---|---|---|---|
| +3 dB | 約 4.3 | −12 | −21 dBFS | 過去回に近い |
| **+5 dB（採用）** | **3.93** | **−8.9** | **−19.9 dBFS** | 明らかに抜けるが過剰ではない |
| +6.9 dB（理論最適） | 3.32 | −5.4 | −17.3 dBFS | 明るいが本番組としては派手 |

参考: 公開済みの #27 のサ行ピークは −22.4 dBFS、#28 は −27.2 dBFS。採用値はそれより 2.5 dB 明るい程度に収めています。

e935 に戻せば、この補正量は **4〜6 dB 程度**で済みます。

### 5-2 Premiere での手順（順序を間違えると取り返しがつかない）

**手順0を飛ばすと以降が全部無駄になります。**

0. **L/R をモノラル2本に分離する。** プロジェクトパネルでクリップを選択 →「クリップ > 変更 > オーディオチャンネル」→ クリップチャンネルフォーマット **モノラル**／オーディオクリップ数 **2**。**タイムラインに乗せてからでは分離できません**（配置前に行う）。
   理由: **「スピーチを強調（Enhance Speech）」は、ステレオクリップに掛けるとモノラルのダウンミックスしか出力しません。** Adobe 公式「Enhance Speech technical requirements」（2026年1月7日更新）に "When you enhance a stereo audio clip, Enhance Speech outputs only a mono downmix of the stereo clip." と明記。本番組の素材は L=リッチャン／R=中塚さんなので、そのまま掛けると**2人が1本に混ざり、以後どちらか片方だけを直すことが永久にできなくなります**。ネストしたシーケンスにも非対応なので「先にネストして一括処理」も使えません。
1. 各モノラルクリップに**スピーチを強調**（Mix Amount 60〜80%。100% は声が作り物になります）
2. **パラメトリックイコライザー**（5-1 の数値）
3. **ディエッサー**
4. **シングルバンドコンプレッサー**（2.5:1 程度）
5. マスタートラックに**ハードリミッター**（最大振幅 −1.0 dB）
6. 書き出し時に「エフェクト」タブの**ラウドネスの正規化**（ITU BS.1770-3）

注意: 分離が 4〜6.5 dB しかないため、**片方だけ深くコンプやゲートを掛けると、相手の声のかぶりがポンピングします**。個別処理は中庸に留めてください。

なお Premiere 本体に**デクリッパーはありません**（Adobe 系では Audition の「診断 > DeClipper」のみで、Audition は Premiere 単体プランに含まれません）。ただし 1 節の通り今回の素材はクリップしていないので、そもそも不要です。

### 5-3 Filmora では仕上げられない（VST3 を入れない限り）

ご契約の2本のうち、**整音は Premiere 一択**です。Filmora（Mac 最新 15.7 / 2026年7月）は次の点で足りません。

- **コンプレッサー／リミッター／ディエッサーが内蔵されていない**（「オーディオエフェクト」カテゴリはオーディオビジュアライザー等の**視覚**効果で、DSP ではありません）
- **EQ がプリセット中心**で、バンド数・中心周波数・dB レンジが公式ドキュメントに記載されておらず、数値の直接入力もできない。5-1 の補正値を入力する手段がない
- **ステレオの L/R を別クリップに分離する機能**が公式ドキュメントに存在しない（＝2人を別々に扱えない）
- AI 音声補正（AI Voice Enhancer）はスライダー2本のみで、歪み・サ行への対応を謳っていない
- デクリップ機能なし

抜け道は1つあります。**14.7.12 以降、64bit VST3 プラグインに公式対応**（Mac 対応。VST2 と音源系は非対応）し、V15 は 32bit オーディオパイプラインです。コンプ／リミッター／ディエッサーを VST3 で外部から持ち込めば成立します。裏を返せば、**VST3 を導入しないなら Filmora で整音を完結させる道はありません**。

### 5-4 買い足しの要否 → 現時点では不要

iZotope **RX Elements（$99）**は De-clip / De-reverb / Voice De-noise / Repair Assistant を含み、VST3 で Premiere Pro 2026 に直接挿せます。ただし本件では優先度が低い。

- **今回の素材はクリップしていない**ため、De-clip は不要（1 節）。
- 効くとすれば回り込み対策の Dialogue Isolate ですが、**分離 4 dB では期待できません**。収録で解決すべき問題です。
- **Premiere は ARA を一切サポートしません。** RX の目玉であるスペクトル編集（Spectral Editor）は ARA 版しか存在せず、Premiere には挿せません。使うなら RX Standard 以上の単体アプリで「書き出し → 処理 → 差し替え」の手動往復になります。
- Accusonus / ERA Bundle は 2026年時点で**新規入手不可**。候補から外してください。

### 5-5 できない
- **回り込みと残響の除去** — 分離 4〜6.5 dB は後から分離できない。
- **コムフィルタの除去** — 加算後に生じたノッチは戻せない。2トラックのまま扱うか、収録で分離を上げるしかない。
- **近接効果の低域** — 80〜160 Hz は信号がノイズフロアと同レベル。
- **Clipping Control の復元** — Mic Mini 2 は送信機内蔵録音が無く、処理前の信号が存在しない。

## 6. ワイヤレスを使い続ける場合（0円の改善）
装着位置を襟の端にして口へ向ける（口から 15〜20 cm）、2人の距離を 70 cm から 1.4 m へ、ハの字配置、ノイズキャンセルを弱／オフ、送信機ゲインを下げてピークを −12〜−18 dBFS に。分離 4 → **10〜13 dB** が見込めます（7 節の通り、無指向性ラベリアである以上これが原理的な上限です）。
Clipping Control は Pocket 3 の 設定 > ワイヤレスマイク にある想定ですが、**公式互換表は「対応機能の一覧」であって UI の設定項目一覧ではない**ため、実機で確認が必要です。オフにする場合は必ず先にゲインを下げること（Mic Mini 2 には保険の内蔵録音が無い）。

## 7. 「絵に入る」問題との両立

音質を決めているのは機材のグレードではなく**口元からの距離**です。6畳相当・残響0.4秒を仮定した直接音対残響音比（D/R）:

| 口元距離 | 直接音（5cm基準） | D/R |
|---|---|---|
| 3 cm（ヘッドセット） | +4.4 dB | 28.2 dB |
| 5 cm（ハンドヘルド近接） | 0 dB | 23.7 dB |
| 10 cm | −6.0 dB | 17.7 dB |
| 15 cm（画角下端に置く） | −9.5 dB | 14.2 dB |
| 20 cm | −12.0 dB | 11.7 dB |
| **現状（胸元ラベリア）** | — | **8〜10 dB（実測）** |

画角の下端ぎりぎりに e935 を置いて口元 15 cm でも、現状より D/R が 4〜6 dB 改善します。

### 3案

| | 内容 | 費用 | 分離 | 絵への影響 |
|---|---|---|---|---|
| **A（音質最良・推奨）** | e935 を「見せるマイク」として画角下端に配置。ラジオ番組らしい画にする | e935 2本目＋スタンド | 20〜25 dB | マイクが映る |
| **B（絵が最もすっきり）** | ヘッドセットマイク（口元 2〜3 cm） | 約 ¥25,000〜35,000 ×2 | 25〜30 dB | 装着が見える |
| **C（費用ゼロ）** | DJI のまま設定と配置だけ直す | 0円 | **10〜13 dB が上限** | 変化なし |

C は無指向性ピンマイクである以上、装着位置と着席間隔を最適化しても **10〜13 dB が原理的な上限**で、A/B の 25 dB 級には届きません。

なお C を選ぶ場合、Clipping Control は**送信機ゲインを 12〜15 dB 下げるだけでほぼ解消できる可能性が高い**です（リミッターのしきい値が固定なら、入力がしきい値に届かなくなるため）。ゲインを下げても天井が動かなければ、リミッターがゲイン段より前にあることになります。テスト録音1回で切り分けられます。

### C の派生案：DJI Mic Mini 2S（2026年8月発売）

Mini 系で初めて**送信機内蔵録音**を搭載しました（内蔵 14.5 GB、32bit float 約22時間／24bit 約28時間）。これがあれば、カメラに送られる音とは**別経路**で無加工の WAV が残るため、Clipping Control も AAC 圧縮も丸ごとバイパスできます。DJI サポート記事では Pocket 3 と Bluetooth 直結・最大2送信機と記載されています。

ただし**この案では「詰まった感じ」の主因は直りません**。内蔵録音が解決するのは 2 つの原因のうち Clipping Control だけで、より支配的な**コムフィルタ（分離 4 dB・遅延 2 ms）は胸元の無指向性ラベリアである限り残ります**。買う前に、DJI の製品ページ側（Pocket & Action 対応表）には Mini 2S が載っておらず記載が食い違っている点を、実機または販売店で確認してください。

> 補足: 32bit float が防ぐのは**デジタル段のオーバーロード**だけで、カプセル自体の音響的な飽和には効きません。そして 1 節の通り、今回の素材はそもそもデジタル段でクリップしていません。「32bit float にすれば MV7 / e935 の音になる」ということはありません。

## 8. 未確認の事項
